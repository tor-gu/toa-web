# toa-web

The static web app for the Tournament of Albums, live at
[toa.tor-gu.com](https://toa.tor-gu.com). It reads everything it displays from the
[toa-api](https://github.com/tor-gu/toa-api) read-only API.

There is no build step — these files are deployed to S3/CloudFront as they are.

## Pages

| File | Content |
|---|---|
| `index.html` | Rankings table, album score history, and match results — one document serving `/`, `/album/<id>` and `/match/<id>` off `location.pathname` via the History API. Script in `app.js`, styles in `index.css` |
| `viz.html` | Score history animated as a D3-force graph, fed by `GET /viz` |
| `about.html` | Static prose |
| `404.html` | The CloudFront error page — self-contained, makes no API calls |

The rest is shared: `theme.css` and `theme.js` hold the design tokens and the header,
navigation tabs and non-prod banner every page gets; `api.js` resolves the API base
URL; `config.js` carries the per-environment runtime config. The `config.js` committed
here is the local-dev default only — deployed environments get theirs generated by
Terraform, so editing this one changes no deployed site.

## Local development

No build step and no test suite. Serve the directory:

```sh
python3 -m http.server 8000 -d .
```

The committed `config.js` points at the prod API, which allows CORS, so this drives
real data. Enter at `/` and click through: in-app navigation never re-requests the
document, but a deep link like `/album/<id>` needs the rewrite a CloudFront Function
performs in production and will 404 against a plain static server.

## Related projects
